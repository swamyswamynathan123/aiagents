# Document Q&A

A LangGraph capstone for retrieval over real files. It ingests Markdown, text and PDF documents,
finds the right passages with hybrid search and re-ranking, and answers with citations that are
checked against the sources. It also refuses when the documents don't cover a question.
The full design write-up is in [guide.md](../../guide.md#12-capstone-document-qa).

| Pattern | Where |
|---------|-------|
| RAG (14), done properly | `ingest.py` (section- and page-aware chunking) + `retrieval.py` (BM25 + vector + RRF + LLM re-rank) |
| Router (03) | After retrieval: nothing relevant → `not_found` without calling the answer model |
| Memory (06) | Conversation per thread; `condense` rewrites follow-ups into standalone questions |
| Structured output (11) | `Answer` (text + found?), `RerankResult`, `Groundedness` |
| Reflection (05) | `check`: code validates citations, an LLM checks every claim against its source; one retry |
| Guardrails | Question guard, **injected passages quarantined at ingestion**, output guard that keeps PII quoted from the cited sources |

```bash
python -m projects.doc_qa.demo "your question"   # sample documents, shows ranks and citations
streamlit run projects/doc_qa/ui.py              # upload files, pick a retrieval mode, chat
python -m projects.doc_qa.retrieval_eval         # retrieval benchmark: hit@1, recall@k, MRR per mode
python -m projects.doc_qa.evals                  # 9 answer scenarios (LangSmith experiment)
pytest tests/test_doc_qa.py                      # 22 offline tests
```

**Sample documents** (`docs/`, generated by `make_docs.py`) describe a fictional company,
Northwind Labs:
- an employee handbook;
- an IT security policy;
- firmware release notes, where one fact changed between versions;
- a 5-page router manual as a **PDF**.

They're designed to exercise retrieval: exact codes (`E204`), paraphrases ("vacation" vs "PTO
accrual"), thresholds ("a $40 taxi" vs "receipts over $25") and conflicting versions.

**Retrieval benchmark** on the sample set (16 labelled questions, k=4):

| Mode | hit@1 | recall@4 | MRR |
|------|------:|---------:|----:|
| bm25 | 81% | 100% | 0.91 |
| vector | 100% | 100% | 1.00 |
| hybrid | 94% | 100% | 0.97 |
| hybrid+rerank | 100% | 100% | 1.00 |

On a small, clean set of documents, vector search alone is already strong, and fusion can lower
the top-1 hit rate. The re-ranker gets it back, and it also enables refusal. See guide §12.4.
Measure on your own documents before choosing a mode.

| File | Role |
|------|------|
| `ingest.py` | Load `.md`/`.txt`/`.pdf`, split by heading/page, contextual chunk headers, quarantine injected passages |
| `retrieval.py` | BM25 (with light stemming), FAISS vectors, reciprocal rank fusion, LLM re-ranker |
| `graph.py` | Graph nodes and `DocQASession`; the retriever travels in the run config, not the checkpointed state |
| `retrieval_eval.py` | The labelled benchmark |
| `make_docs.py` | Writes the sample docs, including the PDF (built-in minimal PDF writer) |
| `demo.py` / `ui.py` / `evals.py` | CLI demo, Streamlit UI, answer evals |
